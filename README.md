# 한녕 — 한·영 자동 전환 입력기

**한녕**은 ‘한영키 이제는 안녕’를 줄인 말로 Mac에서 두벌식 키를 그대로 치면 문맥에 따라 한글·영어·혼합어로 자동 확정하는 InputMethodKit 입력기입니다. 판별은 앱에 들어 있는 로컬 모델이 이 Mac 안에서 합니다.

## 설치

[Releases](https://github.com/gityeop/hannyeong/releases/latest)에서 `Hannyeong-<버전>-arm64.pkg`를 내려받아 엽니다. 설치 프로그램은 Apple 공증을 받았고, 관리자 암호 없이 이 사용자 계정의 `~/Library/Input Methods`에 설치합니다.

- **요구 사항:** Apple Silicon Mac, macOS 15.0 이상. 실제 설치·입력은 macOS 27.2에서 확인했습니다.
- 설치 후 메뉴바 입력 메뉴에서 **한녕**을 선택합니다. 처음 쓸 때 모델을 읽느라 잠시 준비 시간이 걸립니다.
- 메뉴에 한녕이 없으면 **로그아웃 후 다시 로그인**하세요. 최근 macOS는 새 입력 소스를 로그아웃 전까지 목록에 반영하지 않는 경우가 있습니다([Apple 포럼](https://developer.apple.com/forums/thread/775526)). 그래도 없으면 시스템 설정 → 키보드 → 텍스트 입력 → 입력 소스 → 편집 → **+** → 한국어 → **한녕**을 추가합니다.

설정 → 정보 → 업데이트에서 자동 확인과 자동 다운로드·설치를 켜거나 끌 수 있습니다. **업데이트 확인…**으로 즉시 확인할 수도 있습니다. 자동으로 다운로드한 업데이트는 한녕이 종료될 때 적용합니다. 자동 업데이트 기능이 없는 이전 버전은 새 pkg를 내려받아 한 번 설치해야 합니다.

## 사용법

기본 입력은 두벌식 한글입니다. `dkssud`를 치면 Space 전부터 `안녕`이 미확정 문자열로 보이고, Space·Return·숫자·문장부호에서 영문 유지 여부를 판별해 확정합니다. 영어 키도 입력 중에는 두벌식 한글로 보이다가 영어로 판별되면 영어로 바뀝니다.

한글·영어 양쪽으로 읽히는 앞 단어도 Space에서 먼저 확정합니다. 뒤 단어로 언어가 분명해지면 이미 확정한 앞부분까지 함께 고칩니다. 예를 들어 `to `, `go `를 친 뒤에는 `새 해 `가 조합 영역 없이 남고, `home`이나 `home을` 뒤 Space·Return에서 앞부분이 `to go`로 바뀝니다. 끝의 공백을 지웠다 다시 치거나, 확정된 문구에서 커서를 옮겼다가 같은 문구 끝으로 돌아와 이어 쳐도 재교정할 수 있습니다. 자동 교체는 입력란의 위치와 기존 글자가 기록에 일치하는지 확인한 뒤에만 수행합니다. 다른 위치에서 새로 입력하거나 확정된 단어 자체를 삭제하면 그 기록은 해제됩니다. 앞 단어 교정에는 손쉬운 사용 권한이 필요합니다. 설정 → 정보 → 손쉬운 사용 허용...에서 허용한 뒤 macOS의 인증을 완료합니다.

- **오른쪽 ⌘ 한 번:** 입력 중이거나 방금 확정된 단어를 한글↔영어 반대로 바꿉니다. 누를 때마다 한글과 영어 입력 모드가 번갈아 전환됩니다. 바꾼 결과는 기억해서 다음에 같은 키를 치면 문맥과 상관없이 그대로 입력합니다. 실수로 눌렀다면 바로 한 번 더 누르면 원래대로 돌아가고 기억도 지워집니다. 기억한 단어는 설정 → 저장된 교정에서 지울 수 있습니다.
- **오른쪽 ⌘ 빠르게 두 번:** 방금 변환한 단어의 교정 후보창을 엽니다. **1 또는 2**를 누르거나 후보를 클릭하면 글자를 바꾸고 문맥과 함께 기억합니다. ↑↓로 이동하고 Return으로 확정하며 Esc로 취소합니다.
- 단어 뒤에 `.`·`?` 같은 기호와 공백을 입력한 뒤에도 교정할 수 있으며, 기호·공백은 그대로 보존합니다.
- 같은 키 입력을 모든 문맥에서 같은 결과로 고정하려면 설정 → 저장된 교정에서 그 교정의 기억 방식을 ‘항상’으로 바꿉니다.
- **Esc:** 타이핑 중이던 단어를 영어로 반환합니다.


설정 창은 입력 메뉴에서 열거나 다음 명령으로 엽니다.

```sh
open "$HOME/Library/Input Methods/Hannyeong.app" --args --settings
```

## 개인정보

- **판별은 로컬 안에서만 합니다.** 입력 내용은 전송하지 않습니다. 네트워크는 업데이트 확인과 다운로드에 사용합니다.
- **교정과 개인 학습은 로컬에만 저장합니다.** 교정 기록과 개인 보정값은 `~/Library/Application Support/Hannyeong/`에 저장하고 어디에도 전송하지 않습니다. 이 폴더를 지우면 모두 초기화됩니다.
- **진단 로그에는 입력 내용을 남기지 않습니다.**
- **사용 데이터를 수집하지 않습니다.** 분석 도구나 원격 수집 기능이 없습니다.

## 자동 업데이트 배포

공증과 스테이플을 마친 `Hannyeong.app`에서 `scripts/build-update.sh /절대/경로/Hannyeong.app /새/출력/폴더`를 실행하면 서명된 업데이트 ZIP과 `appcast.xml`을 만듭니다. 앱의 버전과 빌드 번호를 이전 배포보다 높여야 합니다. ZIP은 해당 GitHub Release에 올리고, 생성된 `appcast.xml`은 `website/appcast.xml`로 반영해 사이트를 배포합니다. 스크립트는 업로드하거나 사이트를 배포하지 않습니다.

업데이트 서명 키는 이 Mac의 키체인 계정 `com.yeop.inputmethod.Hannyeong`에 있습니다. 처음 서명할 때 macOS가 이 키의 키체인 접근 허용을 요청할 수 있습니다. 개인 키를 저장소에 넣지 않습니다. 공개 키는 앱의 `SUPublicEDKey`에 고정되어 있으므로 이후 배포에서도 같은 서명 키를 사용해야 합니다. 자동 업데이트 기능이 없는 0.4.1 이하 버전은 0.4.2 pkg를 한 번 설치해야 합니다.

로컬 업데이트 엔진 검사: `Tests/Updater/test-updater.sh` (Developer ID 서명 인증서 필요). 실제 Sparkle와 로컬 HTTP 서버를 사용해 버전 판별, 잘못된 피드 처리, 자동 업데이트 설정 저장, 별도 테스트 앱의 다운로드·설치·재실행, 변조된 ZIP 거부를 검사합니다. 설치 검사는 임시 테스트 서명 키를 사용하며 배포 키나 설치된 한녕을 변경하지 않습니다.

실제 Chrome 입력란 검사: `Tests/BrowserSession/test-browser.sh`. 기본 textarea와 서식 있는 입력란에서 두벌식 물리 키를 15ms·120ms 간격으로 입력합니다. 검사 중에는 Chrome을 활성 창으로 유지해야 하며, 설치된 한녕에 손쉬운 사용 권한이 필요합니다.
